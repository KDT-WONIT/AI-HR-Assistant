# 근거를 들어 자연스럽게 답하기

## 이번 변경과 이유

| 변경 | 이유 |
| --- | --- |
| 질문·사용자·업무 결과·문서/페이지/문장 ID를 마크다운 구획으로 전달 | 문서 출처와 사용자 질문의 역할을 구분하기 위해 |
| 모델은 원문을 다시 복사하지 않고 서버가 지정한 문장 근거 ID 선택 | 작은 모델이 제목과 원문을 섞어 복사해 유효한 근거까지 거절되던 문제 해결 |
| 결론 → 필요한 조건/방법 → 문서·페이지·조항 → 미확인 세부사항 안내 | 원문 나열을 줄이고 직원이 바로 이해할 수 있도록 |
| 신청 질문은 최대 3개 질문으로 검색 확장 | '연차 신청'과 '근태계 제출'처럼 표현이 다른 실제 절차를 찾기 위해 |
| 검색 결과 통합·중복 제거·공통 절차 우선 | 유사한 연차 이월 조항만 반복 반환되는 문제 보완 |
| 관련 정보가 있으면 부분 답변, 너무 무관하거나 검증된 근거가 없을 때만 확인 불가 | 직접적인 신청 메뉴가 없다는 이유로 관련 규정까지 모두 숨기지 않도록 |
| 원문은 펼쳐보기, 답변 오류에도 원문 전체로 자동 대체하지 않음 | 날것의 조항·긴 원문이 기본 답변에 노출되던 문제 해결 |
| 출처는 선택한 문장 이전의 조항을 확인 | 같은 조각 끝에 있는 다른 조항 번호가 잘못 붙는 문제 해결 |
| 공통 근태계 근거에 시스템 양식·전자결재 승인이 모두 있으면 요약에도 승인 단계 유지 | 축약된 문장이 필수 승인 조건을 빠뜨리지 않도록 |
| '제한 없이'는 제외/금지로 판정하지 않고 국내·해외 범위는 근거에 맞게 유지 | 과도한 거절과 적용 범위 확대를 줄이기 위해 |

## 연차 신청 질문의 실제 근거

기존 ChromaDB에서 **취업규칙 시행세칙(2025년도 07월 개정).pdf 3쪽 제4조(근태계 제출)**를 찾았습니다.
이 조항은 각종 근태계를 전산시스템 양식에 따라 전자결재 승인을 받아 제출하고,
특별한 사정으로 본인 제출이 불가능하면 소속 부서원이 대리 제출할 수 있다고 규정합니다.

답변은 이것을 **공통 근태계 제출 기준**으로 명시해 제공합니다.
문서에 없는 특정 ERP 제품명, 메뉴 경로, 신청 며칠 전 등의 수치를 만들어내지 않습니다.
관련 연차 사용 기준도 근거가 있으면 안내하되 다른 휴가의 증빙 등록 기한을 연차 신청 기한으로 바꾸지 않습니다.

검색어 확장은 정책을 새로 만드는 것이 아니라 기존 규정의 업무 용어로 검색하는 처리입니다.
ChromaDB를 재생성하거나 원문 데이터를 변경하지 않습니다. 여기서 문장을 나누는 작업은 모델 입력용입니다.

## 주요 파일

- prompts/answer_system.txt: 자연스러운 문장·질문 의도·관련 정보 제공 지침
- app/agent/answers.py: 문장 ID·기본 근거 검사·답변 조립·출처
- app/rag/retrieval.py: 질문 확장·검색 결과 순위
- app/rag/pipeline.py: 묶음 임베딩·분야 필터 검색
- frontend/js/chat.js: 원문/검색 근거 펼쳐보기

근거 ID·수치·부정 표현 검사는 모든 의미적 오류를 증명하거나 검출하는 것은 아닙니다.
관련 내용과 사용 범위를 확인하는 질문으로 품질을 계속 점검해야 합니다.

실제 화면에서 전산시스템 양식 작성·전자결재 승인·대리 제출 안내와 제4조/3쪽 출처를 확인했습니다.
자녀 학자금 질문도 국내대학교의 무이자 대부 근거로 적용 범위를 한정해 답하는 것을 확인했습니다.
최신 품질 검사 15개는 통과했습니다. 전체 재검사에는 Windows 소켓 오류가 남아 있으며 상세는 testing.md에 기록했습니다.

## 금액 질문(연봉·급여): 표 복원과 핵심 내용 출력

"나 연봉 얼마야"에 "직위와 사업소 등급에 따라 결정됩니다"처럼 일반론만 나오던 원인과 개선입니다.

| 원인 | 개선 |
| --- | --- |
| 규정 표가 인덱스에 `11, 1 = 1,240,000. 11, 2 = ...`처럼 평탄화되어 있고 쪽을 넘으면 머리글(대상·등급·직무급·구분)이 사라짐 | `app/rag/tables.py`가 이웃 청크를 ChromaDB에서 읽어 이어 붙여 행(등급·금액·구분)과 표 제목·단위(금액 : 원, 월)를 복원 |
| 짧은 질문만으로는 금액표가 검색되지 않고 개정 이력 표가 상위에 옴 | 금액 질문이면 사용자 직급을 붙인 4개 질의로 확장, 개정 이력 표·임원 규정은 감점 (`app/rag/retrieval.py`) |
| 모델이 수치를 일반론으로 요약하고 point가 3개·350자로 제한됨 | point 최대 6개·500자, summary 600자, `num_predict` 2400, `OLLAMA_NUM_CTX` 12288, 프롬프트에 표 처리 규칙 추가 |
| 모델 품질에 따라 표 내용이 빠짐 | `app/agent/key_content.py`가 사용자 직급(질문에 직급이 있으면 그 직급)의 행을 문서에서 복원한 값 그대로 "핵심 내용"으로 출력 |

- 개인별 확정 연봉액은 급여 자료가 없으면 알 수 없다고 밝히고 `partial`로 분류하여 급여 담당자 카드를 함께 보여줍니다.
- 금액은 문서 값 그대로이며 합산·추정하지 않습니다. 사용자 직위·사업소 구분이 확정되지 않으면 해당 직급의 후보 행을 모두 나열합니다.
- 기존 인덱스는 재적재하지 않고 이웃 청크를 읽기만 합니다. 이웃 조회 실패 시 원본 조각으로 계속합니다.
- 검증: `python -m unittest tests.test_pay_context` (실제 인덱스의 26~27쪽 구조를 옮긴 청크 사용)

## 답변 스트리밍 (POST /api/chat/stream)

화면은 기본으로 이 엔드포인트를 사용합니다. 답변 모델이 생성하는 동안 SSE로 이벤트를 보냅니다.

| 이벤트 | 내용 |
| --- | --- |
| status | 진행 문구(검색 중 / 문서 N개 발견 / 답변 작성 중) |
| delta | 생성 중인 요약·확인된 내용 미리보기(매번 전체 교체) |
| final | /api/chat과 같은 ChatResponse(검증·정리된 최종 답변, 출처, 담당자) |
| error | 오류 문구와 상태 코드 |

미리보기는 모델이 만드는 JSON에서 summary와 points의 text를 읽어 보여줍니다. 생성이 끝나면 서버가 근거 검증을 거친
최종 답변이 미리보기를 교체하므로, 근거가 확인되지 않은 문장이 최종본에 남지 않습니다(그래서 미리보기와 최종 문구가 조금 다를 수 있습니다).
/api/chat(비스트리밍)은 그대로 있어 평가 스크립트 등에서 사용합니다.


## 일반 대화 모드 (맞는 업무 도구가 없을 때)

툴콜링 선택지에 가상 도구 `general`이 있습니다. 사내 업무와 무관한 질문(인사·잡담·상식·글쓰기 등)이면 라우터가 `general`을 고르고, 문서 검색 없이 `prompts/general_system.txt` 기준으로 일반 챗봇처럼 답합니다. 사내 규정·금액·담당자는 지어내지 않고 "규정을 확인한 답변은 아님"을 밝힙니다. 담당자 카드는 질문이 특정 업무 주제와 맞을 때만 붙고 기본 창구(총무/인사/경영기획)는 붙이지 않습니다.
