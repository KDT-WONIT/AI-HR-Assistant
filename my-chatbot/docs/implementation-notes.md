# 추가 구현과 이유

이번 요청에서 결정한 사항과 기존 구현의 빈 부분을 기록합니다.

| 구현 | 이유 |
| --- | --- |
| 공식 SDK 기반 MCP 서버·클라이언트 및 tools/list·tools/call 실제 호출 | 기존 함수 호출에 MCP 이름만 붙이지 않고 표준 경계로 도구를 실행하기 위해 |
| 기존 레지스트리에서 자동 등록 | 도구 개수 변경 시 서버·에이전트 목록이 함께 바뀌도록 |
| stdio 자식 프로세스를 FastAPI가 시작/종료하고 연결 재사용 | 로컬 실행 설정과 터미널 수를 늘리지 않고 임베딩 모델을 매 질문 새로 로딩하지 않도록 |
| Windows Selector 환경에서 MCP만 별도 Proactor 스레드로 전달 | Uvicorn reload의 소켓 재시작과 stdio 자식 프로세스를 모두 지원하기 위해 |
| MCP 서버에서 사용자 정보 재조회·입력 스키마 검증 | 호출자가 임의 프로필을 주입하거나 잘못된 계산 인자를 보내지 않도록 |
| 종료·평가·전송 payload 먼저 저장 후 n8n POST | 기존 전송 자리에는 메시지가 비어 있었고, 외부 장애 시 평가 유실 위험이 있었음 |
| 최근 메시지/글자 수 제한과 기본 프로필만 전송 | 요청한 간단한 대화 데이터를 보내고 문서 원문과 중복 RAG 컨텍스트 전송을 줄이기 위해 |
| 전송 상태·타임아웃·동일 event_id 재전송 버튼 | 실패를 숨기지 않고 저장된 평가를 재입력하지 않아도 재전송할 수 있도록 |
| 실제 MCP 연결 및 로컬 HTTP 수신기 자동 테스트 | 통신 경계·오류·중복 제출과 저장 결과를 함께 확인하기 위해 |

## 실행 범위

SQLite + 기존 ChromaDB + BGE-M3 + Ollama + MCP + HTML/CSS/JS 채팅을 로컬에서 구동할 수 있습니다.
`python -m app --reload`로 실행합니다. 처음 검색 시 임베딩 모델 로딩 시간이 필요합니다.
사용 환경에 requirements.txt 의존성과 .env에서 지정한 Ollama 모델들이 설치되어 있어야 합니다.

공유용 설정 양식의 n8n URL은 빈 값이며 실제 .env의 사용자 설정은 유지합니다.
URL 미설정 시 외부 POST는 없고, 실제 n8n 수신·워크시트 적재는 별도 확인이 필요합니다.
직원 식별은 테스트 사번 입력이며 인증/권한 검증은 아직 구현 범위에 포함되지 않습니다.
규정 답변에는 기본 근거 검사가 있지만 LLM의 모든 의미 오류를 검출하는 것은 아닙니다.
연차 계산은 원장 데이터가 있어야 하며, 미등록이면 추가 정보가 필요하다고 응답합니다.
실제 휴가 승인, 급여 지급, 인사 데이터 변경, n8n 워크플로 작성은 구현하지 않았습니다.

기존 컬렉션 검색과 별개로 새 PDF 추출·분할·인덱스 적재/갱신은 미구현 상태입니다.
현재 서비스 실행에는 사용되지 않으며, 새 문서를 추가하려면 별도의 적재 경로가 필요합니다.
전체 서비스 실제 점검 결과와 남은 작업은 service-status.md에 기록했습니다.

답변 가독성과 근거 활용 보완에서는 마크다운 문맥, 문장 근거 ID, 신청 질문 확장,
공통 절차·관련 정보의 부분 제공, 출처 조항 보정, 원문 펼쳐보기를 추가했습니다.
각 변경 이유와 실제 연차 신청 근거는 answer-quality.md에 기록했습니다.

사원 데이터 연동에서는 employee_directory.sqlite3 읽기 전용 연결, 공통 프로필·역할·연락처·부서 조회,
로컬 이미지 API, 사원 검색·선택 화면, 순수 조회의 RAG 생략을 추가했습니다.
원본 사원 자료와 기존 대화 기록을 보존하면서 화면·MCP·컨텍스트가 같은 정보를 사용하기 위한 변경입니다.
설정·이미지 선택 기준·검사 범위는 employee-directory-integration.md를 참고하세요.

답변이 부족하면 현재 질문의 업무에 맞는 담당자 후보를 사원 DB에서 찾아 카드로 표시합니다.
도구 선택과 별개로 연봉→급여 등 업무 표현을 실제 부서 기능과 연결하고 실무 역할을 우선합니다.
개인별 상세 업무분장표가 없어 확정 담당자 대신 업무 관련 후보로 안내합니다.
LLM의 연락처 생성을 막고 새로고침 후에도 안내가 남도록 DB 조회·설정 파일·기록 복원을 추가했습니다.
추천 기준과 변경 이유, 44개 테스트 및 실제 화면 확인은 contact-escalation.md에 기록했습니다.

단계별 기록 요청에 맞춰 session_start·question·answer·session_end POST를 추가했습니다.
예시의 session_start/question 및 필드명을 유지하고, 답변은 질문과 같은 message_id로 보냅니다.
예시에 없는 답변·만족도 이벤트 이름은 .env에서 바꿀 수 있게 했습니다.
생성 실패 통지·전송 실패 안내는 PENDING 방치와 외부 장애에 따른 대화 중단을 줄이기 위한 추가 구현입니다.
시작·질문·답변은 1회 전송, 종료·만족도는 기존 저장 후 재전송 방식을 유지합니다.
계약과 한계, 변경 이유 및 로컬 수신기로 검증한 42개 테스트는 end-webhook.md에 기록했습니다.
