# 답변 부족 시 관련 업무 담당자 안내

## 동작

규정 답변의 근거 충족 여부가 `partial` 또는 `missing`이면 현재 질문을 기준으로 사원 DB의 관련 업무 담당자 후보를 조회합니다. 충분히 답변한 `direct`이면 추천하지 않습니다. 검색 결과 없음·추가 정보 필요·모델 출력 근거 검증 실패도 안내 대상입니다. 모델 연결 장애나 MCP 통신 장애는 기존 오류 처리를 유지합니다.

**나 연봉 언제 오르지**에 대한 개인별 인상 시점 근거가 부족하면 급여부 실무담당자 카드를 표시합니다. 선택된 규정 도구와 별개로 질문의 업무를 판별합니다. 실제 서비스에서 권나연(WON0015, 내선 2115), 황태윤(WON0016, 내선 2116)이 반환되었습니다.

카드에는 이름·사번·부서·직책·이메일·내선·근무지·업무 역할·로컬 이미지·추천 이유를 표시합니다. 전화번호는 등록된 정보만 안내하며 현재 이미지 자료는 로컬 가상 프로필 아이콘입니다. 담당자에게 전화·메일·알림을 발송하지 않습니다.

## 추천 기준

- 원본: `database/employee_directory/employee_directory.sqlite3`의 실제 부서 기능 및 현재 업무 역할.
- `config/contact_topics.json`의 표현 확장(연봉 → 급여 등)과 실제 부서명·업무 기능을 매칭합니다.
- 부서 관련성 순으로 정렬하며 실무담당자 → 업무대행자 → 부서장 → 승인자를 우선합니다. 동률이면 사번 순입니다.
- 특정 개인의 ID나 연락처를 코드에 고정하지 않습니다. 현재 재직·유효 배치·INTERNAL 연락처가 있는 후보를 사용하며 본인·비공개 연락처·퇴직자는 제외합니다.
- 관련 업무나 연락 가능한 직원이 없으면 사람을 임의로 추천하지 않고 사유를 표시합니다.
- "그럼 어디에 문의해?" 같은 주제 생략 후속 질문에만 같은 세션의 최근 질문을 참고합니다. 현재 질문의 업무가 우선이며 무관한 새 주제에 이전 부서를 재사용하지 않습니다.

현재 자료에는 개인별 세부 업무분장표가 없습니다. 따라서 **부서 기능과 직원 역할로 찾은 문의 후보**라고 표시하며, 해당 사안의 확정 담당자라는 의미는 아닙니다. 연봉 인상 시점을 사번·직급·입사일만으로 추정하지 않도록 답변 지침도 추가했습니다.

## 설정과 저장

| 설정 | 용도 |
| --- | --- |
| CONTACT_RECOMMENDATION_LIMIT=2 | 표시할 후보 수, 1~5명 |
| CONTACT_ROUTING_PATH=./config/contact_topics.json | 질문 표현과 부서 업무의 연결 규칙 |

연결 규칙은 부서 ID 대신 실제 업무 표현을 사용하며 도구 개수와 독립적입니다. 새 업무는 이 파일에서 확장합니다. 설정 변경 후 서버를 재시작합니다.

API의 `contact_escalation`에는 상태(`not_needed`, `recommended`, `not_found`, `unavailable`), 안내 문구와 후보 목록이 들어갑니다. 후보는 `employee`, `reason`, `matched_terms`, `duty_description`, `match_type`으로 구성합니다. 답변 문맥의 `answer_coverage`는 질문에 대한 근거 충족 여부입니다.

기존 assistant 메시지의 `context_data` JSON에 추천을 저장하고 SQLite·MySQL 기록 조회 시 복원합니다. 이전 메시지에 필드가 없으면 `not_needed`로 처리하여 DB 스키마 변경이 필요하지 않습니다. 기존 n8n의 간단한 메시지 전송에는 카드 메타데이터를 추가하지 않습니다.

## 추가 구현과 이유

| 구현 | 이유 |
| --- | --- |
| 답변 근거 충족 여부 구조화 | 문서 검색 성공과 실제 답변 가능 여부를 구분하기 위해 |
| 질문 기반 독립 추천 | 도구 분류와 달라도 실제 문의 업무의 담당 부서를 찾기 위해 |
| DB 후보·실무 역할 우선 | LLM이 사람이나 연락처를 생성하지 않고 등록된 실무 연락처를 안내하기 위해 |
| 업무 표현 설정 파일 | 부서·도구 변화에 맞춰 연결 규칙을 확장하기 위해 |
| 관련성 없음·조회 실패 구분 | 무관한 직원에게 안내하거나 조회 성공으로 오인시키지 않기 위해 |
| 카드 기록 저장·복원 | 새로고침 후에도 당시 안내한 후보를 확인할 수 있도록 |

## 라우팅 개선 (복리후생 질문이 공정계약실로 안내되던 문제)

- 원인: 서로 다른 주제가 같은 점수(예: `복리후생` 10점, `구매계약` 10점)면 둘 다 채택하고 부서별로 한 명씩 보여, 질문에 구매·계약 표현이 섞이면 공정계약실이 후보에 들어왔습니다.
- 질문의 중심 업무 하나만 사용합니다(점수가 같으면 먼저 언급된 주제). "A와 B 둘 다"처럼 여러 업무를 함께 물을 때만 모두 사용하며, 이때는 주제별로 번갈아 후보를 뽑습니다.
- 답변 단계의 선택 도구·검색된 규정 문서명을 보조 근거(`ContactHints`)로 전달합니다. `contact_topics.json`의 `tool_ids`, `source_patterns`로 연결합니다.
- 복리후생은 전담 부서가 없어 인사부·급여부를 같은 순위의 대체 부서로 안내하며 카드에 "전담 부서가 없어 관련 업무 부서로 안내합니다"를 표시합니다.
- 휴양시설·동호회·보육·의료비·식대지원 등 복리후생 표현을 추가했습니다.
