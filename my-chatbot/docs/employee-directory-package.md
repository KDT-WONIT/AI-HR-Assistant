# 사원 · 조직 · 연락처/사진 DB

기존 전사 데이터셋 43개 테이블에서 이번 범위에 필요한 6개만 추출한 독립 DB입니다.
샘플 사번과 사원 데이터는 원본을 유지했습니다. 모든 사원과 연락처는 가상 자료입니다.

| 구분 | 테이블 | 데이터 | 내용 |
| --- | --- | --- | --- |
| 사원 | employees | 100명 | 사번, 이름, 직급, 입사일, 고용형태, 재직상태 |
| 조직 | departments | 16개 | 부서명, 상위 부서, 기능, 근무 위치, 대표 내선 |
| 소속 이력 | employee_assignments | 100건 | 사원·부서 연결, 직책, 유효기간, 주 소속 여부 |
| 업무 역할 | duty_roles | 5개 | 부서장, 실무담당자, 대체담당자, 승인권자 등 |
| 역할 배정 | employee_roles | 100건 | 사원별 역할과 시작·종료일 |
| 연락처·사진 | employee_contacts | 100건 | 이메일, 내선, 근무지, 사진 URL·파일 경로·출처·검수 상태 |

세 종류의 정보를 한 DB 안에서 테이블로 분리하고 사번·부서 ID로 연결했습니다.
사진은 직원당 한 장을 연결하므로 연락처와 같은 테이블에 보관합니다.
부서 이동·겸직은 사원 기본 정보를 덮어쓰지 않고 소속 이력으로 관리합니다.
현재 자료의 상위 부서 ID는 모두 비어 있어 실제 조직 계층을 임의로 만들지 않았습니다.
업무 역할은 담당 업무 구분이고 로그인 권한은 아닙니다.

## 바로 열어보기

`employee_directory.sqlite3`는 사원 데이터까지 입력된 SQLite DB입니다.
SQLite를 지원하는 DB 도구에서 바로 열 수 있고 별도 계정·서버가 필요하지 않습니다.
`queries_sqlite.sql`에 사번 조회, 부서별 직원, 조직 현황, 연락처 검색, 사진 상태 조회 예제가 있습니다.
`v_employee_profiles`는 직원 한 명의 현재 소속·연락처·사진을 합쳐 보여주는 뷰입니다.
소속 유효기간은 시작일·종료일을 포함하며 현재 날짜는 한국 시간 기준입니다.
원본의 사원 100명은 현재 모두 재직 상태이고 부서별 현재 인원 합계는 100명입니다.

## MySQL에서 생성

MySQL Workbench에서 다음 파일을 순서대로 실행합니다.

1. `01_create_schema.sql`: 독립 DB `employee_directory`와 6개 테이블·조회 뷰 생성
2. `02_seed_data.sql`: 가상 사원·조직·연락처·사진 데이터 등록
3. `03_example_queries.sql`: 조회 예제

기존 `enterprise_ai_agent` 및 앱의 대화 DB와 별도 이름을 사용합니다.
MySQL 8.0 이상 기준입니다. 생성 계정에는 DB·테이블·뷰 생성 권한이 필요합니다.
재적재 시 같은 기본키는 변경하지 않습니다. 다른 고유키 충돌 등 오류 발생 시 실행을 중단하고 `ROLLBACK`하세요.
앱에 통합할 때는 기존 `python -m scripts.init_db`, `python -m scripts.seed_employees`를 사용할 수 있습니다.
이 독립 SQLite 파일을 앱의 전체 저장소로 바로 지정하면 대화 테이블이 없으므로 별도 앱 초기화가 필요합니다.
현재 앱 설정과 기존 대화 데이터는 이 DB 묶음 생성 과정에서 바꾸지 않습니다.

## 사진

`assets/profiles/`에 사원별 기본 SVG 아이콘 100개를 포함했습니다.
Pexels 사진은 원본의 후보 URL과 출처 페이지·라이선스 URL을 저장했습니다.
원본 JPG는 내려받지 않았고 `REVIEW_PENDING` / `NOT_DOWNLOADED` 상태를 유지합니다.
화면에서는 우선 `fallback_photo_path`의 기본 아이콘을 사용할 수 있습니다.
모든 파일 경로는 이 DB 묶음 폴더 기준 상대 경로이며 브라우저 URL은 아닙니다.

## 원본에서 선택한 내용

| 원본 파일 | 사용 방식 |
| --- | --- |
| 01_create_schema.sql | 6개 테이블의 관계·필드 확인, 프로젝트의 강화된 제약조건 사용 |
| 02_seed_data.sql | 선택한 6개 테이블의 실제 INSERT 값과 CSV를 전 필드 대조 |
| 03_example_queries.sql | 사원 디렉터리 조회 방식을 참고해 범위에 맞는 예제로 재작성 |
| 04_load_csv.py | 테이블 순서를 참고하고 원본 로더는 실행하지 않음 |
| 04_OLD_randomuser_do_not_run.sql | 구버전 사진 데이터이므로 적용하지 않음 |
| 04_update_100_pexels_photos.sql | 사원 100명의 최신 사진 필드와 설명 반영 |

급여·근태·연차·규정 문서·상담·대화 관련 테이블은 이 묶음에서 제외했습니다.
원본 SQL 파일은 수정하지 않았습니다.
프로젝트 호환을 위해 `employee_name`은 `name`, `hire_date`는 `hired_at`으로 바꿨고 생성시각을 추가했습니다.
사진 출처 페이지·라이선스는 원본 `docs/employee_photo_manifest_100.csv`에서 보완했습니다.
`source_manifest.json`에는 원본 6개 파일의 SHA-256과 테이블별 행 수가 기록됩니다.

## 다시 생성

프로젝트 `my-chatbot` 폴더에서:

```powershell
.\.venv\Scripts\python.exe -m scripts.build_employee_directory --output-dir database/employee_directory_new
```

기존 결과 폴더가 있으면 덮어쓰지 않고 중단합니다. 새로운 폴더 이름을 지정하세요.
SQL/CSV 불일치, 사번 참조 오류, 중복, 사진 매핑 누락 등이 있으면 생성하지 않습니다.

## 검증 결과

2026-11-04, 생성된 SQLite 파일의 무결성·외래키 검사를 통과했습니다.
사원 조회, 부서별 인원, 최신 사진 패치·기본 아이콘, 기존 결과 덮어쓰기 방지 등을 테스트했습니다.

6개 테이블의 모든 행이 SQLite 파일과 일치하는 것을 확인했습니다.
