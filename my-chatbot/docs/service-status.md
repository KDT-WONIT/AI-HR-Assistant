# 전체 서비스 구동 점검 — 2026-11-04

현재 PC에서 기존 ChromaDB를 사용하는 로컬 데모를 구동할 수 있습니다.
웹 서버와 Ollama가 실행 중이며 http://127.0.0.1:8000/ 에서 사용합니다.

## 이번 실제 검증

- FastAPI 상태: live / chat_available=true
- SQLite 연결 정상. 이후 사원 연동에서는 employee_directory의 100명·부서 16개를 사용자 원본으로 연결했습니다. 이전 대화 DB의 직원 102행은 유지합니다.
- MCP stdio 연결 정상: 분야 도구 9개
- Ollama 사용 모델: 도구 선택·답변 모두 gemma4:e2b
- 실제 질문 2회를 연속 실행하여 두 번 모두 answered, pay_benefits 선택, 문서 근거 5개를 확인
- 두 번째 질문의 컨텍스트에 이전 메시지 2개와 현재 사용자 프로필 포함
- SQLite에서 질문/답변 총 4개 복원 확인
- 만족도 neutral 제출 후 대화 closed 및 웹훅 not_configured 확인

실제 n8n 주소는 비어 있어 외부 POST는 하지 않았습니다.
웹훅 POST 자체의 성공·503·타임아웃·재전송·중복 제출 처리는 앞선 로컬 HTTP 수신기 테스트에서 검증했습니다.

## 남은 설정 및 미구현 범위

| 항목 | 현재 상태 | 사용 전 필요한 작업 |
| --- | --- | --- |
| n8n 실제 워크시트 저장 | 발신 POST 기능은 구현됨, URL은 요청대로 빈 값 | .env의 N8N_WEBHOOK_URL에 전체 주소를 넣고 서버 재시작 후 수신·열 매핑 확인 |
| 잔여 연차 계산 | 조회/계산 함수는 구현됨, 연차 원장 0건 | employee_id,year,granted_days,used_days CSV 등록 |
| 새 PDF 적재·기존 인덱스 갱신 | 현재 기존 ChromaDB 검색은 정상. app/rag/loader.py의 추출·분할과 vector_store.build는 미구현/차단 상태 | 새 문서 적재가 필요할 때 별도 컬렉션 생성·검증·전환 기능 구현 |
| 로그인·권한 | 테스트 사번으로 식별 | 실제 직원 데이터를 사용하는 서비스 전환 시 인증과 사용자별 접근 통제 구현 |
| 전송 중 강제 종료 복구 | sending 상태의 자동 회수/백그라운드 재시도 없음 | 운영 자동 복구가 필요하면 전송 작업의 만료·재시도 정책 추가 |

연차 원장은 다음 명령으로 등록할 수 있습니다. 배포된 예시 CSV는 헤더만 있으므로 데이터 행을 작성해야 합니다.

```console
python -m scripts.import_leave_balances --file data/raw/leave_balances.example.csv
```

새 PDF는 chroma_db 폴더에 파일을 복사하는 것만으로 검색에 포함되지 않습니다.
현재 경로에는 이미 만들어진 Chroma 컬렉션을 두어야 합니다.
연차 부여 일수·급여 지급·휴가 승인 등의 업무 규칙과 실적은 임의로 만들어 넣지 않았습니다.

## 이번 점검에서 변경한 내용과 이유

실제 실행을 막는 새 코드 누락은 발견하지 않았습니다. 이 상태 문서와 README 링크를 추가했습니다.
이유는 실행 가능한 범위와 데이터 등록/추가 개발이 필요한 범위를 구분해 재현 가능하게 남기기 위해서입니다.
앞서 추가한 구현과 판단 이유는 implementation-notes.md에 기록되어 있습니다.

## 실행

프로젝트 루트에서 필요한 의존성이 설치된 Python 환경으로 실행합니다.

```console
python -m app --reload
```

현재 8000번 포트에 서버가 실행 중이면 브라우저에서 새 대화를 시작하면 됩니다.
