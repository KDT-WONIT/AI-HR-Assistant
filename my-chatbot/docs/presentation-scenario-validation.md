# 발표 시나리오 검증 및 수정 기록

검증일: 2026-11-05. 한 직원이 같은 채팅에서 1~12번을 순서대로 진행했습니다. 실제 Ollama(`gemma4:e2b`), stdio MCP, 기존 ChromaDB, SQLite를 사용했습니다.

최종 원본 결과는 `logs/presentation-accepted.json`, 읽기 쉬운 전체 질문·답변은 [실제 응답 기록](presentation-scenario-transcript.md)에 있습니다. 초기 결과는 `logs/presentation-baseline.json`에 보존했습니다.

## 검증 조건

- 등록된 가상 직원: WON0002 / 이준호 / 인사부 / 3직급.
- 국내 출장: 부산, 2026-10-19~11-08, 20박 21일. 본사와 다른 시군, 왕복 600km.
- KTX 왕복 100,000원, 숙박 20박 × 80,000원, 식비 대상 21일. 회사 제공 숙소·식사 없음.
- 배우자는 11월 9일 둘째 아이 **한 명** 출산 예정. 둘째 자녀와 다태아는 구분했습니다.
- 연차는 별도 테스트 DB에만 2026년 부여 23일, 사용 8일을 등록했습니다. 실제 연차 사용 이력을 조사한 값이 아닙니다.
- 테스트 세션 ID: `8a6a3efd-424d-4b7f-9e0d-b0350ca87f94`.
- 기본 서비스 DB와 직원 원본 DB는 변경하지 않았습니다. `.env`도 변경하지 않았습니다. 테스트 프로세스의 환경 변수에서만 외부 n8n 주소를 비웠습니다.

## 발견한 문제와 수정 이유

1. **후속 질문의 대상이 사라짐**: ‘이 경우 지원금’에 금품 수수 한도 규정이 검색되고 ‘그 휴가’가 다른 휴가로 해석됐습니다. 같은 세션의 최근 사용자 발언을 최대 30개까지 별도로 읽어, 필요한 발언만 검색 질문에 덧붙입니다. 답변 모델의 최근 대화는 기존 10개 제한을 유지합니다. 다른 세션과 과거 AI 답변은 이 사실 참조에 포함하지 않습니다.
2. **질문을 다시 쓰는 과정에서 의도가 바뀜**: 모델만으로 재작성하면 ‘며칠?’이 ‘사용 가능 여부’로 바뀌었습니다. 질문 원문을 유지하고 사용자 발언을 구분된 참고 블록에 넣는 방식으로 수정했습니다. 명시적인 새 주제에는 이전 상황을 붙이지 않습니다.
3. **9번에서 첫 출장 조건 누락**: 최근 5턴만으로는 첫 날짜·거리·숙박비가 사라졌습니다. 같은 세션의 앞선 명시적 출장 조건을 다시 참조하고, KTX·왕복 거리·시군·밤 수·식비 일수 등 명시된 값이 모델 인자와 충돌하면 사용자 값을 우선합니다.
4. **지급일 질문에서 여비 계산 재실행**: 과거 ‘계산해줘’가 현재 질문에 섞였습니다. 도구의 계산 실행 여부는 현재 질문 원문으로 판단하고, 지급일 질문의 계산 인자를 비웁니다. 국내 출장에 모델이 붙인 국외 환율·품의일 인자도 제거합니다.
5. **다른 휴가와 연차 원장 혼동**: 경조휴가 며칠 질문에도 연차 잔여일수가 붙었습니다. 연차 원장 조회는 연차 질문으로 한정했습니다.
6. **기본 20일·예외 25일과 유산/사산 5일 혼동**: 출산 관련 별표·공통 절차를 추가 검색하고, 관련 없는 해외근무·유산/사산·다른 경조휴가 행을 우선 근거로 사용하지 않도록 제한했습니다. 배우자 출산휴가 일수는 검색된 표에서 기본·예외 숫자를 읽어 직접 정리합니다. 20일이라는 답을 상수로 고정하지 않았으며 표가 없으면 임의로 만들지 않습니다.
7. **신청의 필수 단계 누락**: 전자결재만 안내하고 증빙 첨부나 사전 허가가 빠졌습니다. 검색된 공통 근태계·특별유급휴가 근거에서 확인된 단계를 정리해 표시합니다.
8. **일반 권리를 실제 일정 승인으로 단정**: 연차 사용 권리만으로 복귀 없는 휴가·연속 사용이 승인된 것처럼 말했습니다. 직접적인 일정 승인 근거가 없으면 확인이 필요한 부분으로 구분합니다.
9. **질문 핵심보다 주변 규정이 먼저 나옴**: 출산축하금 액수 미확인, 실제 입금일 미확인을 첫 문장에 명시합니다. 복명서 제출 기한과 계좌 지급일을 구분합니다. 휴가 답변에는 항목 수를 채우기 위한 원문 자동 덧붙이기를 하지 않습니다.

주요 수정 파일: `app/agent/followups.py`, `service.py`, `answers.py`, `business_answers.py`, `leave_answers.py`, `travel_answers.py`, `app/integrations/ollama.py`, `trip_input.py`, `app/rag/retrieval.py`, `pipeline.py`, `app/tools/execution.py`, 각 저장소의 사용자 발언 조회, `prompts/answer_system.txt`.

도구 목록은 계속 MCP에서 동적으로 받아 Ollama가 선택합니다. 도구 수를 9개로 고정하지 않았습니다. 중요한 휴가 표·신청 요건·여비 계산의 정형 표시를 제외한 일반 규정 설명은 Ollama 답변 생성과 근거 검증을 유지합니다.

## 검증 범위와 남은 데이터

- 회귀 검사 **137개 통과**: 발표 맥락·답변·급여 46개, API·새 UI 25개, SQLite·일반 대화·MCP 26개, 담당자·웹훅 40개. 모의 외부 장애 검사의 503 로그와 ML 패키지가 없는 단위 검사 환경의 워밍업 경고는 예상된 결과입니다. 실제 모델·검색 검증은 별도의 Python 3.13 환경에서 수행했습니다.
- 실제 모델 전체 시나리오 최종 실행은 질문 처리 합계 약 36.9초였습니다. 한 번의 로컬 실행 기록이며 성능 보장은 아닙니다.
- 화면 검사는 별도 `logs/presentation-ui.sqlite3`를 사용했습니다. 기존 8000번 서버를 중단하지 않았고, 임시 8012번 서버는 검사 후 종료했습니다.
- n8n에 실제 POST를 보내거나 Google Sheets의 저장 결과를 확인하지 않았습니다. 기존 기능의 로컬 전송·오류 처리 검사는 통과했고, 전체 시나리오에서는 `not_configured`로 격리했습니다.
- **기본 서비스의 `leave_balances`는 현재 0행입니다.** 발표에서 실제로 잔여 15일을 보이려면 연차 원장을 등록해야 합니다. 예제 파일 `data/examples/presentation_leave_balances.csv`는 가상 발표 자료임을 구분해 두었으며 기본 DB에 자동 등록하지 않았습니다. 기존 적재 명령은 `python -m scripts.import_leave_balances --file data/examples/presentation_leave_balances.csv`입니다. 이 명령을 직접 실행하면 현재 설정된 DB의 해당 사번·연도 원장을 등록/갱신합니다.
- **출산축하금의 실제 금액표, 실제 여비 입금 일정, 복귀 없는 휴가·연속 사용의 개별 승인 기록은 제공된 자료에 없습니다.** 이 부분은 추가 자료 없이는 확정 답변을 만들지 않습니다. 관련 부서의 사원 DB 연락처를 추천합니다.
- 표의 의미가 바뀌거나 외부 준용 지침의 금액표가 추가되면 추가 검증이 필요합니다. 현재 규정 파일의 오탈자(예: ‘8울’)는 원본 출처명 그대로 유지했습니다.

## 다시 실행하기

Chroma·임베딩·Ollama가 설치된 서비스 실행 환경에서 프로젝트 루트를 기준으로 실행합니다.

```console
python -m scripts.evaluate_presentation --phase demo-001
```

`phase`는 영문 소문자·숫자·하이픈만 사용합니다. 기존 테스트 DB가 있으면 덮어쓰지 않고 중단하므로 새 이름을 사용하세요. 결과 JSON·라우팅 기록·SQLite는 `logs/presentation-{phase}*`에 남습니다. 이 검사는 자체 프로세스에서 외부 n8n 주소를 비웁니다.
