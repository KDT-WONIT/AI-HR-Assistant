# 툴콜링 오작동 방지 방안

"개인 이메일로 보내도 되나요?"라는 규정 질문에 직원 연락처 목록이 나온 사례처럼, 질문이 엉뚱한 도구로 가거나 도구가 단어 하나에 반응해 관련 없는 결과를 내는 문제를 막기 위한 방법입니다.

## 문제가 생기는 두 지점

1. **라우팅**: AI가 질문을 어느 도구로 보낼지 매번 다르게 고를 수 있습니다.
2. **도구 내부**: 도구가 '이메일', '연락처' 같은 키워드만 보고 조회하거나, 조회 결과가 있으면 규정 검색을 건너뜁니다.

## 방지 방법

| 방법 | 내용 | 장점 | 한계 |
|---|---|---|---|
| 1. 라우터 프롬프트 보강 | 도구 설명에 "하지 않는 일"과 헷갈리는 질문 예시를 넣습니다. | 구현이 간단합니다. | 모델 판단이라 100% 보장되지 않습니다. |
| 2. 규칙 기반 우선 분기 | 잔여 연차, 출장비 계산처럼 의도가 뚜렷한 질문은 라우터를 거치지 않고 도구로 보냅니다. | 결과가 항상 같습니다. | 규칙이 늘면 관리가 어렵습니다. |
| 3. 조회 의도 확인 | 도구는 "찾는 질문"일 때만 조회하고, 허용 여부·절차를 묻는 표현이 있으면 조회하지 않습니다. | 키워드 오작동을 직접 막습니다. | 표현 사전을 계속 보완해야 합니다. |
| 4. 결과 검증(사후 안전망) | 도구가 가져온 데이터가 질문 의도와 맞는지 확인하고, 맞지 않으면 버리고 규정 검색으로 답합니다. | 라우팅이 틀려도 피해가 커지지 않습니다. | 의도 판단 기준이 필요합니다. |
| 5. 폴백 검색 | 도구 결과가 비면 다른 분야까지 규정 검색을 확장합니다. | 답변을 못 찾는 경우가 줄어듭니다. | 지연이 늘 수 있습니다. |
| 6. 평가 회귀 세트 | 헷갈리기 쉬운 질문을 케이스로 저장해 수정할 때마다 `python -m scripts.evaluate`로 확인합니다. | 같은 문제가 다시 생기는 것을 막습니다. | 케이스를 계속 추가해야 합니다. |
| 7. 라우터 신뢰도 기준 | 분류 확신이 낮으면 도구를 쓰지 않고 일반 규정 검색이나 되묻기로 보냅니다. | 틀린 도구 호출을 줄입니다. | 모델이 신뢰도를 안정적으로 내야 합니다. |

## 이 프로젝트에서 추천하는 조합: 2 + 3 + 4 + 6

라우터(1, 7)는 모델에 의존하므로 보조로만 두고, 코드로 보장할 수 있는 층을 겹겹이 둡니다.

1. **우선 분기(2)**: 내 연차 잔여 질문과 출장비 계산은 라우터와 상관없이 전용 도구로 보냅니다. (적용 완료: `app/agent/service.py`)
2. **조회 의도 확인(3)**: 연락처 조회는 "알려줘·주소·누구" 같은 찾는 표현이 있고 허용 여부 표현이 없을 때만 실행합니다. (적용 완료: `app/agent/intent_guard.py`의 `is_contact_lookup`)
3. **결과 검증(4)**: 도구 실행 직후 `drop_unrelated_directory_data`가 조회 의도가 없는 질문에 붙은 사원·연락처 데이터를 제거합니다. 그러면 규정 검색 답변이 정상으로 이어집니다. (적용 완료: `app/tools/execution.py`의 `execute_domain`)
4. **평가 회귀 세트(6)**: `data/eval/cases.json`에 `guard-` 로 시작하는 케이스 4개를 추가했습니다. 개인 이메일 반출, 연락처 외부 공유, 부서 이동 절차, 업무용 번호 SNS 게시 질문에서 직원 목록이 나오면 실패로 처리합니다.

## 운영 방법

- 새 도구나 키워드 분기를 추가할 때는 "이 단어가 들어간 규정 질문"을 `guard-` 케이스로 같이 추가합니다.
- 실제 Ollama를 켠 상태에서 `python -m scripts.evaluate`를 실행해 `guard-` 케이스가 모두 통과하는지 확인합니다.
- 서버 로그에 `조회 의도가 없어 사원·연락처 데이터를 제외했습니다` 가 자주 보이면 해당 질문이 잘못 분류되고 있다는 신호이므로, 그 질문을 라우터 도구 설명의 예시에 추가합니다.

## 일반 대화(general) 선택 기준

도구는 업무 분야 9개 + 일반 대화(`general`) 1개입니다. 인사말·잡담이 업무 도구로 가서 "검색된 자료만으로는 확실하게 정리하기 어렵습니다"가 나오지 않도록 세 겹으로 판단합니다. (`app/agent/intent.py`)

1. **라우터 앞(규칙)**: "안녕하세요", "고마워요", "너는 누구야?" 같은 인사·감사·작별·챗봇 소개 질문은 업무 단어가 없으면 모델 판단 없이 바로 일반 대화로 보냅니다.
2. **라우터(모델)**: 프롬프트에 선택 기준 4개와 예시를 넣었습니다. 업무 단어가 하나라도 있으면 업무 도구, 업무와 무관하면 general, 후속 질문은 직전 도구를 따릅니다.
3. **라우터 뒤(안전망)**: 모델이 업무 도구를 골랐더라도 질문에 업무 관련 단어가 없고, 이전 대화도 업무 대화가 아니며, 도구가 만든 조회·계산 데이터도 없으면 규정 검색 결과를 버리고 일반 대화로 답합니다.

업무 질문인데 일반 대화로 빠지면 `BUSINESS_TERMS`에 단어를 추가하고, 반대로 잡담이 업무로 가면 `CHITCHAT` 패턴을 보완합니다. 평가 케이스 `general-*` 3개가 이를 확인합니다.
