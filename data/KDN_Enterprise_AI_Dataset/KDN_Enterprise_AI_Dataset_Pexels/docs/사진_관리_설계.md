# 직원 사진 저장과 담당자 카드 구현 기준

## 결론
MySQL에는 사진 바이너리(BLOB) 대신 사진 파일 경로(`photo_path`) 또는 권한 있는 이미지 URL(`photo_url`)만 저장하는 구조가 적합합니다.

- 데모: ZIP 내부 `assets/profiles/KDN0001.svg` ~ `KDN0100.svg` (총 100개, 그림 아바타)
- DB: `employee_contacts.photo_path = profiles/KDN0001.svg`
- HTML 데모: 파일 경로로 아바타 표시
- 운영 환경: 내부 파일 저장소 또는 인증된 객체 스토리지의 이미지를 제공하는 서버가 사진 URL을 발급
- 사진을 실제 사람 얼굴로 오인하지 않도록 가상 프로필임을 표시

## 사진 교체 절차
1. 가상 직원 1명당 고유한 AI 생성 프로필 이미지를 준비 (예: `KDN0001.webp`). 실제 사람의 얼굴을 무단으로 사용하지 않음.
2. 이미지 저장소 `assets/profiles/KDN0001.webp`에 저장.
3. SQL로 직원 프로필 데이터 수정.

```sql
USE enterprise_ai_agent;
UPDATE employee_contacts
SET photo_path = 'profiles/KDN0001.webp',
    photo_url = NULL,
    photo_status = 'READY',
    photo_source = 'AI_GENERATED'
WHERE employee_id = 'KDN0001';
```

4. 서버는 파일 경로를 검증 후 내부 `/static/profiles/KDN0001.webp`처럼 제공. 외부에 민감한 정보가 노출되지 않도록 권한 확인.

## Python FastAPI 이미지 정적 경로 예시 (실습용 공개 샘플 파일에 한정)
```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles
from pathlib import Path

app = FastAPI()
app.mount('/static', StaticFiles(directory=str(Path(__file__).parent / 'assets')), name='static')
# 브라우저 URL: http://127.0.0.1:8000/static/profiles/KDN0001.svg
```

실제 임직원 사진은 위처럼 무조건 공개되는 StaticFiles가 아니라 세션 권한 검사 또는 서명된 URL 방식 사용 권장.

## 담당자 카드 조회 예시
```sql
SELECT topic_name, dept_name, employee_name,
       extension_number, work_email, photo_path, photo_url
FROM enterprise_ai_agent.v_topic_contact_cards
WHERE topic_name LIKE '%사택%';
```

## 주의
- 현재 사번 입력만으로 개인 데이터를 조회하는 것은 인증에 해당하지 않음.
- `example.com` 메일은 테스트용이므로 실제로 발송하면 안 됨.
- BLOB이 원천적으로 잘못된 것은 아니며, 조직 규모·규정에 따라 DB 바이너리 저장이 필요할 수도 있지만 이 미니프로젝트에는 비효율적임.
